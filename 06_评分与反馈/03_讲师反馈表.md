# 讲师反馈表

讲师反馈建议“少而具体”：先确认已经完成的部分，再指出最影响结果可用性的 1-3 个修改点。

| 学员 | 作业 | 当前版本 | 主要优点 | 关键风险 | 需要修改的 1-3 点 | 下一步动作 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  | v1 / v2 |  | 无 / 事实 / 合规 / 语气 / 数据 |  |  |

## 反馈分层

| 层级 | 适合怎么说 | 代表含义 |
| --- | --- | --- |
| 先肯定完成 | “这一版已经把核心结构搭出来了。” | 对方已经有可修改对象 |
| 再指出关键问题 | “目前最影响可用性的是这里缺少产品事实。” | 不是全盘否定，只抓重点 |
| 给具体动作 | “请补充 3 条真实评论，再让 AI 重新归纳痛点。” | 反馈要能马上执行 |
| 约定复评标准 | “改完后我们看它是否能被陌生同事读懂。” | 让修改有判断依据 |

## 常见问题与具体反馈

| 问题 | 不建议的反馈 | 更具体的反馈 |
| --- | --- | --- |
| 太泛 | “再具体一点。” | “请补充平台、目标用户、价格段和使用场景，否则 AI 会写成通用文案。” |
| 太像 AI | “AI 味太重。” | “这 3 句有夸张和套话，请改成用户能感受到的产品事实。” |
| 缺少判断 | “要自己改。” | “请标出你删掉、保留、改写的部分，并写一句理由。” |
| 不能复用 | “沉淀一下。” | “请把这次流程整理成 5 步模板，下次换产品也能用。” |
