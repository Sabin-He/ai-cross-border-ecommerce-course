# 结业评估表

结业评估不看“有没有很厉害”，而看是否完成一个小而真实的改进，并留下之后还能继续用的材料。

| 评估项 | 完成标准 | 好结果 | 需要补充 | 是否完成 |
| --- | --- | --- | --- | --- |
| 真实项目 | 项目来自真实工作，且范围足够小 | 3-7 天内能完成一个版本 | 项目太大、太抽象或无法验证 |  |
| 项目初稿 | 至少有 v1 | v1 能看出结构和主要内容 | 只有想法，没有可看的结果 |  |
| 修改稿 | 至少有 v2 | v2 相比 v1 更清楚、更具体、更可用 | 只是换句子，没有实质变好 |  |
| 人工修改记录 | 标出修改点和原因 | 能看出人做了判断 | 完全看不出人改了什么 |  |
| 风险检查 | 检查事实、合规、隐私、夸大表达 | 风险点有标注和处理 | 可能直接误用或对外发布 |  |
| 固化成模板 | 能下次复用 | 有模板、清单、SOP 或提示词 | 只留下了一次性结果 |  |
| 7 天计划 | 课后能继续使用 | 每天任务小、明确、可检查 | 计划太大或没有检查方式 |  |

## 结业展示提纲

1. 我原来的问题是什么。
2. 我为什么选择这个小项目。
3. AI 帮了哪些步骤。
4. 我人工修改了哪些地方，为什么这样改。
5. v2 比 v1 具体变好了哪里。
6. 最终留下了什么可复用材料。
7. 接下来 7 天我会怎样继续使用。

## 结业自评提示词

```text
请你根据下面的结业项目材料，帮我做一次结业自评。请按“真实项目、项目初稿、修改稿、人工修改记录、风险检查、固化成模板、7 天计划”七项打分，每项给出：是否完成、证据、最需要补充的一点。最后请用温和但具体的语言，给我 3 条下一步建议。
```
