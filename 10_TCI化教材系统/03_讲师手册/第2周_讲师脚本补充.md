# 第 8 章讲师手册：从“会用 AI”到“用 AI 做工作”

## 1. 本章教学目标

让学员从临时问 AI 转向把 AI 放进一个固定岗位动作，并完成《岗位提效诊断表》。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，10 分钟讲动作诊断，10 分钟演示，15 分钟填写，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲风险/重复度，15 分钟演示，20 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲岗位动作，20 分钟案例，32 分钟实操，10 分钟互评，5 分钟提醒 |

## 3. 开场引导话术

```text
会用 AI 不等于工作变轻。真正的变化，是你能指出一个重复动作，知道 AI 帮哪一步，人检查哪一步。
```

## 4. 核心讲解要点

- 岗位提效从具体动作开始，不从岗位职责开始。
- 优先选择高重复、低风险、可检查的动作。
- 高风险动作可以让 AI 辅助，但不能让 AI 决定。
- 诊断表要写清输入、输出和人工检查点。

## 5. 案例演示流程

1. 展示一位运营的一天工作记录。
2. 把动作放进“重复程度 / 风险”表格。
3. 判断哪个动作适合先试点。
4. 写出 AI 可辅助步骤和人工检查点。

## 6. 课堂提问

1. 你每天最重复的 3 个动作是什么？
2. 哪个动作出错影响最小？
3. 这个动作的输出结果怎么检查？

## 7. 实操巡视重点

- 是否写岗位职责而不是具体动作。
- 是否选择了高风险决策动作。
- 是否缺少可检查输出。

## 8. 点评话术

```text
这里写的是职责，不是动作。可以把“负责广告”改成“每天 10 点检查广告异常指标”。
```

```text
这个动作风险偏高，可以先让 AI 做资料整理，人再判断结果。
```

## 9. 常见卡点

| 卡点 | 回应方式 |
| --- | --- |
| 写得太大 | 追问今天具体做了什么动作 |
| 只看省时间 | 加入风险和复核标准 |
| 不知道输出 | 要求写一个文件、表格或清单 |

## 10. 课后提醒

提交 `Day08_岗位提效诊断表_姓名_v1`。提醒学员 Day09 开始用岗位动作支撑广告素材方向。

# 第 9 章讲师手册：AI 辅助广告素材方向

## 1. 本章教学目标

让学员把广告素材从随机灵感变成可测试假设，并完成《广告素材方向表》。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲假设，12 分钟演示，15 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲素材方向，15 分钟演示，20 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲痛点/钩子/证明，20 分钟案例，32 分钟实操，10 分钟互评，5 分钟提醒 |

## 3. 开场引导话术

```text
广告素材不是抽盲盒。我们不是追求一次想出最好创意，而是先把测试方向说清楚。
```

## 4. 核心讲解要点

- 一个素材方向只验证一个主要假设。
- 痛点要来自产品理解、评论或客服反馈。
- 钩子可以直接，但不能夸大。
- 证明点必须真实可展示。

## 5. 案例演示流程

1. 展示一个产品和 3 条用户痛点。
2. 用 AI 生成 5 个方向。
3. 删除无法证明或太夸张的方向。
4. 保留 3 个可测试方向。

## 6. 课堂提问

1. 这个素材到底想验证什么？
2. 这个证明点能不能真的拍出来？
3. 如果下周复盘，如何判断这个方向是否有效？

## 7. 实操巡视重点

- 是否一个方向塞多个假设。
- 是否缺痛点来源。
- 是否写了无法证明的承诺。

## 8. 点评话术

```text
这个方向有吸引力，但同时讲了两个假设。建议先拆成两个素材方向。
```

```text
这个钩子太像承诺效果了，可以改成更具体的使用场景。
```

## 9. 常见卡点

| 卡点 | 回应方式 |
| --- | --- |
| 灵感太散 | 回到痛点、钩子、证明点 |
| 素材方向太多 | 先保留 3 个可测试方向 |
| 证明点不足 | 补产品事实或拍摄条件 |

## 10. 课后提醒

提交 `Day09_广告素材方向表_姓名_v1`。提醒学员 Day10 会用数据复盘这些方向。

# 第 11 章讲师手册：AI 辅助客服和售后回复

## 1. 本章教学目标

让学员整理高频客服问题，并生成可人工审核的 FAQ 与回复库。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，10 分钟讲回复边界，10 分钟演示，15 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲情绪/事实/规则，15 分钟演示，20 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲升级人工边界，20 分钟案例，32 分钟实操，10 分钟互评，5 分钟提醒 |

## 3. 开场引导话术

```text
客服 AI 不是无人自动回复。它更像草稿助手，帮我们先写一版，人负责语气、规则和承诺边界。
```

## 4. 核心讲解要点

- 先处理情绪，再讲事实和规则。
- 回复前必须核对政策。
- 订单号、地址、邮箱等敏感信息不能直接输入 AI。
- 敏感投诉、退款争议和账号问题要标转人工。

## 5. 案例演示流程

1. 展示一条脱敏物流延迟投诉。
2. 让 AI 生成回复草稿。
3. 标出过度承诺和需要人工确认的信息。
4. 改成最终回复。

## 6. 课堂提问

1. 这条客户消息里的情绪是什么？
2. 哪句话可能承诺过度？
3. 这条问题是否需要转人工？

## 7. 实操巡视重点

- 是否输入了客户敏感信息。
- 是否承诺补偿或退款。
- 是否没有转人工边界。

## 8. 点评话术

```text
这版语气已经温和了，但这里承诺了补偿，需要先确认店铺政策。
```

```text
这条回复可以先安抚情绪，再说明查询路径。不要一开始就讲规则。
```

## 9. 常见卡点

| 卡点 | 回应方式 |
| --- | --- |
| 语气太硬 | 先安抚，再说明 |
| 承诺过度 | 标待确认或转人工 |
| 忽略平台规则 | 要求核对政策 |

提交 `Day11_客服FAQ与回复库_姓名_v1`。提醒学员不要提交真实客户记录。

# 第 12 章讲师手册：AI 辅助运营周报

## 1. 本章教学目标

让学员把周报从流水账改成“数据、变化、原因、动作、风险”的工作记录。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲周报结构，12 分钟演示，15 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲原因假设，15 分钟演示，20 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲数据口径，20 分钟案例，32 分钟实操，10 分钟互评，5 分钟提醒 |

## 3. 开场引导话术

```text
周报不是证明自己很忙，而是帮助团队看见变化，并知道下周怎么做。
```

## 4. 核心讲解要点

- 数据不要多，关键就够。
- 原因是假设，不能没有证据就写成事实。
- 下周动作要有负责人、时间和验收标准。
- 风险提醒比长篇总结更有价值。

## 5. 案例演示流程

1. 展示一组周度运营数据。
2. 请学员圈出 3 个变化。
3. 用 AI 生成周报初稿。
4. 人工补充事件背景和风险提醒。

## 6. 课堂提问

1. 这份周报里最重要的变化是什么？
2. 哪个原因还只是猜测？
3. 下周动作有没有负责人和完成标准？

## 7. 实操巡视重点

- 是否把流水账当周报。
- 是否把原因猜测写成事实。
- 是否缺下周动作负责人或完成标准。

## 8. 点评话术

```text
这里写了很多工作，但还没有说清业务发生了什么变化。
```

```text
这个原因需要补证据。可以先写成“可能与库存接近预警有关，需继续确认”。
```

## 9. 常见卡点

| 卡点 | 回应方式 |
| --- | --- |
| 数据太多 | 只保留关键变化 |
| 原因写死 | 改成假设和待确认 |
| 动作太泛 | 写负责人、时间、完成标准 |

## 10. 课后提醒

提交 `Day12_运营周报模板_姓名_v1`。提醒学员先脱敏数据口径。

# 第 13 章讲师手册：把一个动作变成 SOP

## 1. 本章教学目标

让学员把一个重复动作整理成别人能照着做的 SOP。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，10 分钟讲 SOP 五要素，10 分钟演示，15 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲输入/步骤/输出/检查/异常，15 分钟演示，20 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲异常处理，20 分钟案例，32 分钟实操，10 分钟互评，5 分钟提醒 |

## 3. 开场引导话术

```text
SOP 不是厚制度，而是给下一次执行的导航。它要让别人少问你几次。
```

## 4. 核心讲解要点

- SOP 至少包含输入、步骤、输出、检查、异常。
- 步骤要按真实顺序写。
- 检查标准要能判断是否合格。
- 异常处理决定 SOP 是否真的能用。

## 5. 案例演示流程

1. 选择“广告复盘”或“客服 FAQ 整理”动作。
2. 口述当前做法。
3. 用 AI 整理成 SOP 初稿。
4. 人工补充检查标准和异常处理。

## 6. 课堂提问

1. 这个 SOP 执行前要准备什么？
2. 哪一步最容易被新人漏掉？
3. 遇到什么情况必须暂停或升级？

## 7. 实操巡视重点

- 是否只写原则，没有步骤。
- 是否缺输入资料。
- 是否缺异常处理。

## 8. 点评话术

```text
这个步骤还是太抽象。可以写成具体动作，比如“导出过去 7 天广告数据”。
```

```text
这里需要补一个异常处理：如果数据缺字段，先暂停，不要让 AI 猜。
```

## 9. 常见卡点

| 卡点 | 回应方式 |
| --- | --- |
| 步骤太粗 | 拆成能照做的动作 |
| 没检查标准 | 补合格/退回条件 |
| 异常缺失 | 加暂停、升级、补资料规则 |

## 10. 课后提醒

提交 `Day13_岗位SOP模板_姓名_v1`。提醒学员 Day14 要把岗位材料整理成一个包。

# 第 14 章讲师手册：第 2 周复盘，建立岗位 AI 实战包

## 1. 本章教学目标

让学员把第 8 到第 13 章的材料整理成可复用、可交接、能衔接第 3 周项目的岗位包。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲岗位包，12 分钟整理，15 分钟展示，5 分钟提醒 |
| 60 分钟 | 5 分钟开场，10 分钟讲结构，20 分钟整理，20 分钟点评，5 分钟提醒 |
| 90 分钟 | 8 分钟开场，12 分钟讲结构，30 分钟整理，30 分钟展示互评，10 分钟衔接第 3 周 |

## 3. 开场引导话术

```text
如果这些文件不整理，下周又会散掉。今天要做的不是新增内容，而是把有用的工具放到一个工作台上。
```

## 4. 核心讲解要点

- 岗位包要有场景、工具、流程、反馈和索引。
- 只保留会再次使用的材料。
- 每个文件都要写使用场景、输入资料和人工检查点。
- 第 14 章要为第 3 周真实项目做准备。

## 5. 案例演示流程

1. 展示广告岗位包首页。
2. 放入岗位诊断表、素材方向表、广告复盘表和 SOP。
3. 为每个文件写一句使用说明。
4. 选择一个第 3 周候选项目。

## 6. 课堂提问

1. 你的岗位包服务哪个岗位或场景？
2. 哪 3 个文件最可能下周继续用？
3. 第 3 周你想用哪个真实项目验证这套包？

## 7. 实操巡视重点

- 是否只是堆文件。
- 是否缺首页索引。
- 是否没有第 3 周候选项目。

## 8. 点评话术

```text
这个包内容很多，但缺少使用顺序。建议先补一页首页索引。
```

```text
这个文件可以保留，但要写清输入资料和人工检查点，否则别人不知道怎么用。
```

## 9. 常见卡点

| 卡点 | 回应方式 |
| --- | --- |
| 材料太散 | 按场景、文件、用途、检查点整理 |
| 不知道怎么展示 | 用首页索引带路 |
| 和第 3 周断开 | 选一个真实候选项目 |

## 10. 课后提醒

提交 `Day14_岗位AI实战包_姓名_v1`。提醒学员 Day15 会从候选项目中选一个进入落地闭环。
