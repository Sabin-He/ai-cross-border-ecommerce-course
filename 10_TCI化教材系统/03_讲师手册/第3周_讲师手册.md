# 第 3 周讲师手册

本文件按 v0.5 交付准备标准整理第 3 周讲师手册。第 3 周的重点是陪跑真实项目，不是继续扩展新工具。

## 第 3 周授课主线

```text
选项目 -> 拆步骤 -> 做 v1 -> 收反馈 -> 改 v2 -> 固化模板 -> 7 天计划 -> 成果包
```

讲师要反复提醒：

- 本周只做一个小项目。
- 第一版先求能看、能改、能反馈。
- AI 是整理和起草助手，人负责取舍和边界。
- 结营展示用交付物和版本变化说话，不夸大效果。
- 所有业务资料先脱敏，最终判断由人确认。

# 第 15 章讲师手册：选择一个真实项目

## 1. 本章教学目标

让学员从多个想法中选出一个小、真、可完成、可复用的项目，并完成《落地项目选择表》。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲四维选择法，10 分钟演示，15 分钟填写，7 分钟点评 |
| 60 分钟 | 5 分钟开场，10 分钟讲方法，12 分钟案例演示，25 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲方法和边界，15 分钟演示，35 分钟实操，12 分钟互评，5 分钟提交提醒 |

## 3. 开场引导话术

```text
第 3 周我们不再撒大网。只选一个项目，做出来，比同时开五个头更重要。

今天不追求选最宏大的项目，而是选一个一周内能完成、能反馈、能复用的小项目。
```

## 4. 核心讲解要点

- 真：项目来自当前真实工作。
- 小：一周内能做出 v1、收反馈、改 v2。
- 有资料：没有输入资料的项目先不选。
- 可复用：做完后能变成模板或流程。
- 有边界：必须写清本周不做什么。

## 5. 案例演示流程

1. 展示 3 个脱敏候选项目。
2. 用“价值、难度、资料、周期”四维表比较。
3. 复制项目选择提示词，让 AI 输出初筛表。
4. 标出 AI 推荐中需要人工确认的地方。
5. 人工选定 1 个项目，并写清不做事项。

## 6. 课堂提问

1. 这个项目一周后能交付什么文件？
2. 它需要哪些现成资料？
3. 哪部分范围必须先砍掉？

## 7. 实操巡视重点

- 候选项目是否至少 3 个。
- 是否把岗位职责写成了项目。
- 是否写清最终交付物。
- 是否出现多个“最终选择”。
- 是否包含客户、订单、账号、成本等敏感信息。

## 8. 点评话术

```text
这个项目真实，但范围偏大。你可以先缩成一个模板或一张表。
```

```text
这个项目有资料，可以进入本周闭环。建议再补一句：为什么最终选它。
```

```text
AI 的推荐只能作为参考，最终选择理由需要你自己写清楚。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 项目太大 | 想做整套店铺优化 | 缩小到一个 Listing、一个 FAQ、一个 SOP |
| 资料不足 | 只有想法，没有输入资料 | 要求先补评论、广告数据、客服记录或旧文件 |
| 依赖太多 | 需要多部门确认才能开始 | 先选自己能推进的一段 |
| 听 AI 推荐 | 不写自己的判断 | 要求写出选择理由和不做事项 |

## 10. 课后提醒

提交 `Day15_落地项目选择表_姓名_v1`。提醒学员保留候选项目表、最终选择理由、本周不做事项和人工确认点。

# 第 16 章讲师手册：把项目拆成小步骤

## 1. 本章教学目标

让学员把 Day15 选定的项目拆成 5 到 7 个能执行、能检查、能留下文件的小步骤，并完成《项目拆解表》。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲拆解规则，10 分钟演示，17 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲方法，12 分钟案例演示，23 分钟实操，8 分钟点评 |
| 90 分钟 | 8 分钟开场，15 分钟讲输入/动作/输出/检查，20 分钟演示，32 分钟实操，10 分钟互评，5 分钟提交提醒 |

## 3. 开场引导话术

```text
项目不是靠热情完成的，是靠一个个小步骤推进的。今天要把大任务切成能下手的小块。
```

## 4. 核心讲解要点

- 每一步都要有输入资料。
- 每一步都要有动作，不写空泛动词。
- 每一步都要有输出文件。
- 每一步都要有人工检查标准。
- 单步尽量控制在 30 到 90 分钟。

## 5. 案例演示流程

1. 展示一个 Day15 选定项目。
2. 先写最终交付物。
3. 倒推 5 到 7 个步骤。
4. 用 AI 生成拆解初稿。
5. 人工删掉过大步骤，补上检查标准。

## 6. 课堂提问

1. 这一步开始前需要什么资料？
2. 做完后留下什么文件？
3. 哪一步最适合今天先做？

## 7. 实操巡视重点

- 步骤是否像任务清单，而不是愿望。
- 是否缺少输入资料。
- 是否每一步都有输出。
- 是否把“复核”写成独立动作。
- 是否有依赖别人确认的步骤。

## 8. 点评话术

```text
这一步还是太大，可以再拆成“整理资料”和“生成第一版”两步。
```

```text
这里已经有动作了，但还缺检查标准。做完后怎么判断合格，需要写出来。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 只写大阶段 | 调研、生成、优化 | 追问具体资料、动作和输出 |
| 没有输出物 | 做完无法验收 | 要求每步留下表、文档或清单 |
| 步骤过多 | 拆成十几步 | 合并低价值动作，保留关键路径 |
| 让 AI 决定 | 写“AI 判断是否可行” | 改成人工检查标准 |

## 10. 课后提醒

提交 `Day16_项目拆解表_姓名_v1`。提醒学员明天只根据拆解表完成 v1，不临时扩大范围。

# 第 17 章讲师手册：完成第一版

## 1. 本章教学目标

让学员在时间盒内完成能看、能改、能收反馈的项目 v1，并标出待确认内容。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲 v1 标准，8 分钟演示，19 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，10 分钟讲方法，12 分钟演示，25 分钟实操，8 分钟收反馈问题 |
| 90 分钟 | 8 分钟开场，12 分钟讲时间盒，15 分钟演示，40 分钟实操，10 分钟互看，5 分钟提交提醒 |

## 3. 开场引导话术

```text
第一版不是毕业作品。它的价值是让你获得反馈，所以清楚比漂亮重要。
```

## 4. 核心讲解要点

- v1 要能看懂目标和结构。
- 先搭骨架，再填核心内容。
- 不确定内容必须标出来。
- 反馈问题要具体，不问“你觉得怎么样”。
- 不要为了完美拖延到没有版本。

## 5. 案例演示流程

1. 打开项目拆解表。
2. 选择今天能完成的关键步骤。
3. 用 AI 生成 v1 骨架。
4. 人工补资料、删猜测、标待确认。
5. 写出 2 到 3 个反馈问题。

## 6. 课堂提问

1. 这版别人能看懂你想做什么吗？
2. 哪些内容还没有确认？
3. 你想让别人重点反馈什么？

## 7. 实操巡视重点

- 是否还在准备资料，没有产出 v1。
- 是否让 AI 编造没有提供的内容。
- 是否标出待确认项。
- 是否准备了具体反馈问题。
- 是否保留文件版本。

## 8. 点评话术

```text
这版不用追求完整，但需要把待确认的地方标出来。
```

```text
现在最重要的是让别人能给反馈。建议把目标和反馈问题放到开头。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 追求完美 | 一直改，不提交 | 限定 20 分钟交 v1 |
| 内容太散 | 看不出目标 | 先补项目目标和使用对象 |
| 没有待确认项 | AI 猜测被当事实 | 要求逐条标“已确认/待确认” |
| 反馈问题太泛 | 只问“怎么样” | 改成结构、清晰度、可用性问题 |

## 10. 课后提醒

提交 `Day17_项目v1初稿_姓名_v1`，同时提交 2 到 3 个反馈问题。提醒学员不要把 v1 当终稿。

# 第 18 章讲师手册：反馈和修改

## 1. 本章教学目标

让学员把反馈分类、判断是否采纳，并把项目 v1 修改成 v2。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲反馈分类，10 分钟演示，17 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，10 分钟讲取舍，15 分钟案例演示，22 分钟实操，8 分钟互评 |
| 90 分钟 | 8 分钟开场，15 分钟讲分类和取舍，20 分钟演示，32 分钟实操，10 分钟展示，5 分钟提醒 |

## 3. 开场引导话术

```text
反馈不是否定，而是帮项目校准方向。今天练的是怎么判断哪些反馈该采纳。
```

## 4. 核心讲解要点

- 反馈分为事实错误、结构问题、表达问题、业务建议、个人偏好。
- 不是所有反馈都采纳。
- 采纳要说明理由，不采纳也要说明理由。
- v2 的修改要回到项目目标。
- AI 可以帮分类，但不能替人决定。

## 5. 案例演示流程

1. 展示一个 v1 片段和 5 条反馈。
2. 用 AI 做反馈分类。
3. 人工判断采纳与否。
4. 修改成 v2 片段。
5. 填写反馈修改记录表。

## 6. 课堂提问

1. 这条反馈属于哪一类？
2. 它是否符合项目目标？
3. 如果不采纳，理由是什么？

## 7. 实操巡视重点

- 是否把所有反馈都采纳。
- 是否没有写不采纳理由。
- 是否只改文字，不改结构问题。
- 是否有事实或规则待确认。
- 是否保留 v1 和 v2 对比。

## 8. 点评话术

```text
这条反馈很具体，优先处理；这条更像个人偏好，可以先暂不采纳。
```

```text
这里需要写清为什么改。以后复用时，修改理由比漂亮表达更重要。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 反馈太多 | 不知道先改哪条 | 先处理事实错误和结构问题 |
| 不敢拒绝反馈 | 全部采纳 | 回到项目目标判断 |
| 只润色语言 | 没解决业务问题 | 追问这次修改解决了什么 |
| 没有证据 | 把建议写成事实 | 标记待确认 |

## 10. 课后提醒

提交 `Day18_反馈修改记录表_姓名_v1` 和项目 v2。提醒学员保留 v1，不要覆盖原文件。

# 第 19 章讲师手册：固化成模板

## 1. 本章教学目标

让学员把项目 v2 中稳定可复用的部分提取成模板，并明确变量字段、示例和人工检查点。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲固定结构和变量，10 分钟演示，17 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，12 分钟讲模板化，12 分钟演示，23 分钟实操，8 分钟互看 |
| 90 分钟 | 8 分钟开场，15 分钟讲模板化标准，20 分钟演示，32 分钟实操，10 分钟展示，5 分钟提醒 |

## 3. 开场引导话术

```text
如果成果只解决这一次，下次还是从零开始。今天要把稳定结构留下，把变化内容变成变量。
```

## 4. 核心讲解要点

- 模板不是把内容锁死。
- 固定结构和变量要分清。
- 变量用【】标出来。
- 模板要有示例和人工检查点。
- 模板必须去掉敏感信息和一次性细节。

## 5. 案例演示流程

1. 展示项目 v2。
2. 圈出固定结构。
3. 把产品名、时间、数据、场景改成变量。
4. 用 AI 提取模板初稿。
5. 人工补示例、检查点和使用边界。

## 6. 课堂提问

1. 哪些字段每次都不变？
2. 哪些内容下次要替换？
3. 使用后必须检查什么？

## 7. 实操巡视重点

- 是否只是复制 v2，没有变量化。
- 是否保留客户、订单、账号等敏感信息。
- 是否缺少使用场景。
- 是否缺少人工检查点。
- 是否能给别人独立使用。

## 8. 点评话术

```text
这里还太像原项目。把具体产品名、时间和问题改成变量，会更容易复用。
```

```text
这个模板已经有结构了，建议再补一个脱敏示例，别人更容易照着填。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 模板太具体 | 下次不能复用 | 改成变量字段 |
| 模板太空 | 只有标题 | 补示例和填写说明 |
| 没有检查点 | 用完不知道对错 | 加人工检查清单 |
| 保留敏感信息 | 示例含真实信息 | 换成脱敏样例 |

## 10. 课后提醒

提交 `Day19_模板固化表_姓名_v1`。提醒学员明天要把这个模板放进 7 天计划，而不是只存档。

# 第 20 章讲师手册：做一个 7 天微计划

## 1. 本章教学目标

让学员把可复用模板放回真实工作节奏，设计 7 天可执行的小计划。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲微计划，10 分钟演示，17 分钟实操，5 分钟点评 |
| 60 分钟 | 5 分钟开场，10 分钟讲原则，12 分钟演示，25 分钟实操，8 分钟互评 |
| 90 分钟 | 8 分钟开场，15 分钟讲场景绑定，18 分钟演示，34 分钟实操，10 分钟展示，5 分钟提醒 |

## 3. 开场引导话术

```text
课程结束后能不能继续用，不靠热情，靠小到能执行的计划。
```

## 4. 核心讲解要点

- 每天只安排一个小动作。
- 绑定真实工作触发场景。
- 每天要有小交付物。
- 第 7 天要复盘和更新模板。
- 计划太满会降低执行概率。

## 5. 案例演示流程

1. 展示一个可复用模板。
2. 找到真实触发场景。
3. 用 AI 生成 7 天计划初稿。
4. 人工删掉太大的动作。
5. 补上每日交付物和复盘问题。

## 6. 课堂提问

1. 你第 1 天会在哪个真实场景使用模板？
2. 这个动作 30 分钟内能开始吗？
3. 第 7 天准备更新什么？

## 7. 实操巡视重点

- 是否每天安排多个任务。
- 是否没有绑定真实场景。
- 是否缺少每日交付物。
- 是否第 7 天没有复盘。
- 是否把计划写成空泛目标。

## 8. 点评话术

```text
这份计划太满了。建议每天只保留一个小动作，先让它能坚持 7 天。
```

```text
这里可以写得更具体：什么时候打开模板，用在哪个真实工作场景里。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 计划过满 | 每天多项任务 | 限制每天一个动作 |
| 没有触发点 | 想起来再做 | 绑定会议、日报、上架、客服整理等场景 |
| 没有产出 | 做了但无文件 | 要求每日留下一个小交付物 |
| 不复盘 | 第 7 天还在新增 | 安排模板更新 |

## 10. 课后提醒

提交 `Day20_7天AI使用计划_姓名_v1`。提醒学员结营展示时只说可执行计划，不承诺无法验证的业务结果。

# 第 21 章讲师手册：结营复盘，建立个人 AI 落地成果包

## 1. 本章教学目标

让学员整理 21 天成果，展示真实项目链路、版本变化、可复用模板和后续计划。

## 2. 建议时间安排

| 版本 | 节奏 |
| --- | --- |
| 45 分钟 | 5 分钟开场，8 分钟讲成果包结构，12 分钟整理，15 分钟展示点评，5 分钟收尾 |
| 60 分钟 | 5 分钟开场，10 分钟讲结构，20 分钟整理，20 分钟展示点评，5 分钟收尾 |
| 90 分钟 | 8 分钟开场，12 分钟讲结构，25 分钟整理，35 分钟展示互评，10 分钟下一步计划 |

## 3. 开场引导话术

```text
结营不是写一句“我学到了很多”，而是用交付物说明：我解决了什么，怎么改进，下次怎么复用。
```

## 4. 核心讲解要点

- 成果包用文件说话。
- 展示 v1 到 v2 的变化。
- 写清 AI 辅助和人工修改。
- 不夸大效果，只写可验证变化。
- 后续 7 天计划要小到能执行。

## 5. 案例演示流程

1. 展示成果包首页。
2. 按 Day15 到 Day20 放入文件。
3. 展示 v1 到 v2 的一处变化。
4. 说明这个变化来自哪条反馈。
5. 展示模板和 7 天计划。

## 6. 课堂提问

1. 你最能代表进步的前后版本是哪一组？
2. 哪个模板以后还能继续用？
3. 下一轮 7 天项目是什么？

## 7. 实操巡视重点

- 成果包是否只有感想，没有文件。
- 是否缺 v1 到 v2 对比。
- 是否没有写人工判断。
- 是否夸大 AI 效果。
- 是否包含敏感资料。

## 8. 点评话术

```text
这份成果包的价值在于能看到版本变化。建议再补一条“为什么这样修改”的说明。
```

## 9. 常见卡点

| 卡点 | 表现 | 回应方式 |
| --- | --- | --- |
| 只有总结 | 没有文件证据 | 要求补交付物清单 |
| 过度包装 | 夸大结果 | 改成可验证变化 |
| 缺人工判断 | 只贴 AI 输出 | 补修改理由和确认点 |
| 计划太远 | 写长期愿景 | 缩成下一轮 7 天动作 |
