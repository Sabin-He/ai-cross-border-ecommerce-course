# 单章交付物评分标准

本文件覆盖第 2 周各章交付物评分标准。第 10 章《广告数据复盘表》保留最完整评分样板，其他章节沿用“真实问题、输入资料、AI 输出、人工判断、复用价值”的基本结构。

---

# 第 8 章：《岗位提效诊断表》评分标准

## 1. 交付物要求

学员提交：

```text
Day08_岗位提效诊断表_姓名_v2
```

必须包含：岗位名称、至少 8 个真实动作、频率、风险、输入、输出、AI 可辅助步骤、人工检查点、1 个试点动作。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 动作真实 | 来自实际工作记录 | 部分动作偏泛 | 写成岗位职责 |
| 风险判断 | 能区分低中高风险 | 有风险判断但理由少 | 只看 AI 能不能做 |
| 输入输出 | 每个动作都有输入和输出 | 部分动作不完整 | 看不出怎么执行 |
| 试点选择 | 高重复、低风险、可检查 | 试点略大但可拆 | 一开始选高风险任务 |
| 人工检查 | 检查点具体 | 检查点偏泛 | 没有人工检查 |

## 3. 通过标准

- 至少 8 个岗位动作。
- 选出 1 个低风险试点动作。
- 写清 AI 辅助步骤和人工检查点。

# 第 9 章：《广告素材方向表》评分标准

## 1. 交付物要求

学员提交：

```text
Day09_广告素材方向表_姓名_v2
```

必须包含：至少 3 个素材方向、目标人群、痛点、钩子、场景、证明点、测试假设、人工确认项。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 痛点来源 | 来自评论、客服或产品卡 | 有痛点但证据弱 | 凭空想象 |
| 钩子 | 直接但不夸张 | 有吸引力但偏泛 | 夸大或虚假 |
| 证明点 | 真实可拍、可展示 | 需要补证据 | 无法证明 |
| 测试假设 | 一个方向一个假设 | 假设略混杂 | 一个素材讲太多 |
| 复盘衔接 | 能进入数据复盘 | 复盘指标不清 | 无法判断效果 |

## 3. 通过标准

- 至少 3 个方向。
- 每个方向只验证一个主要假设。
- 已标出需要人工确认的证明点。

# 第 10 章：《广告数据复盘表》评分标准

## 1. 交付物要求

学员提交：

```text
Day10_广告数据复盘表_姓名_v2
```

内容必须包含：

- 广告对象。
- 数据周期。
- 脱敏数据。
- 指标观察。
- 异常点。
- 可能原因。
- 证据或待确认项。
- 下周 1 到 3 个动作。
- 人工修改说明。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 真实问题 | 复盘对象和周期清楚，来自真实工作 | 有广告数据，但目标不够清楚 | 看不出要解决什么业务问题 |
| 输入资料 | 数据脱敏，字段足够支撑判断 | 数据可用，但缺少部分关键字段 | 数据太少，或包含敏感信息 |
| 指标观察 | 能看到曝光、点击、转化、花费之间的关系 | 只观察到部分指标 | 只盯一个数字下结论 |
| 假设与证据 | 能区分现象、假设、证据和待确认项 | 有原因分析，但证据不足 | 把 AI 猜测当成事实 |
| 人工判断 | 明确写出人工修改点和判断理由 | 有修改，但理由不清楚 | 直接复制 AI 输出 |
| 下一步动作 | 3 个以内，具体且能执行 | 动作有参考价值，但偏泛 | 动作过多，或直接让 AI 决定预算 |
| 复用价值 | 可保存为下次复盘模板 | 下次可参考，但需要较多调整 | 做完一次就不能复用 |

## 3. 建议分值

总分 100 分。

| 维度 | 分值 |
| --- | ---: |
| 真实问题 | 15 |
| 输入资料 | 15 |
| 指标观察 | 15 |
| 假设与证据 | 20 |
| 人工判断 | 15 |
| 下一步动作 | 15 |
| 复用价值 | 5 |

## 4. 讲师快速点评表

| 问题 | 是 / 否 | 备注 |
| --- | --- | --- |
| 是否写清广告对象和周期 |  |  |
| 是否已脱敏 |  |  |
| 是否把现象和假设分开 |  |  |
| 是否写出证据或待确认项 |  |  |
| 是否有人工修改说明 |  |  |
| 是否没有让 AI 直接决定预算 |  |  |
| 下周动作是否不超过 3 个 |  |  |

## 5. 点评句式

可以直接使用：

```text
这份复盘的优点是对象和周期很清楚，数据能支撑基本判断。
```

```text
这里的原因还只是猜测，需要补一个证据，比如素材内容、页面信息或受众设置。
```

```text
下一步动作可以再具体一点，从“优化素材”改成“把素材 A 前 3 秒改成使用场景展示”。
```

```text
预算相关建议需要人工判断，不能直接采纳 AI 的结论。
```

## 6. 通过标准

满足以下条件即可视为通过：

- 复盘对象和周期清楚。
- 数据已脱敏。
- 至少写出 2 个异常点。
- 至少写出 2 条证据或待确认项。
- 下周动作不超过 3 个。
- 有人工修改说明。

# 第 11 章：《客服 FAQ 与回复库》评分标准

## 1. 交付物要求

学员提交：

```text
Day11_客服FAQ与回复库_姓名_v2
```

必须包含：至少 5 个脱敏客服问题、问题分类、回复草稿、人工确认项、转人工判断、最终回复。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 脱敏处理 | 无客户隐私 | 基本脱敏 | 含订单、地址、联系方式 |
| 问题分类 | 分类清楚 | 分类偏粗 | 混在一起 |
| 回复质量 | 温和、清楚、有边界 | 能用但模板化 | 冷硬或过度承诺 |
| 规则检查 | 标出不能承诺内容 | 有提醒但不具体 | AI 直接承诺 |
| 转人工 | 条件清楚 | 条件偏泛 | 没有升级机制 |

## 3. 通过标准

- 至少 5 个问题。
- 已脱敏。
- 每条都有人工确认项。
- 敏感问题标出转人工。

# 第 12 章：《运营周报模板》评分标准

## 1. 交付物要求

学员提交：

```text
Day12_运营周报模板_姓名_v2
```

必须包含：时间范围、数据来源、核心指标、主要变化、可能原因与证据、下周动作、风险提醒。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 数据选择 | 5 个以内核心指标 | 指标略多 | 堆数据和截图 |
| 变化判断 | 重点清楚 | 变化描述偏泛 | 只写做了什么 |
| 原因证据 | 有证据或待确认项 | 有假设但证据弱 | 把猜测当事实 |
| 下周动作 | 有负责人、时间、标准 | 动作可参考但不细 | 没有执行标准 |
| 风险提醒 | 具体可处理 | 有提醒但偏泛 | 没有风险意识 |

## 3. 通过标准

- 有时间范围和数据来源。
- 能区分事实、假设和动作。
- 下周动作可执行。

# 第 13 章：《岗位 SOP 模板》评分标准

## 1. 交付物要求

学员提交：

```text
Day13_岗位SOP模板_姓名_v2
```

必须包含：SOP 名称、适用场景、输入资料、操作步骤、输出结果、检查标准、异常处理、版本号。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 可执行性 | 新人能照着做 | 大体能懂 | 只是原则 |
| 输入输出 | 清楚完整 | 部分不清 | 缺输入或输出 |
| 操作步骤 | 顺序真实、动作明确 | 有步骤但偏粗 | 跳步严重 |
| 检查标准 | 能判断是否合格 | 标准偏泛 | 无法验收 |
| 异常处理 | 有暂停、复核、升级 | 有提醒但不细 | 无异常处理 |

## 3. 通过标准

- 有五件套：输入、步骤、输出、检查、异常。
- 至少 3 个检查项。
- 至少 2 个异常处理条件。

# 第 14 章：《岗位 AI 实战包》评分标准

## 1. 交付物要求

学员提交：

```text
Day14_岗位AI实战包_姓名_v1
```

必须包含：岗位包首页、服务场景、至少 3 个可复用文件、至少 1 个 SOP、反馈标准、第 3 周候选项目。

## 2. 评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 首页索引 | 一眼能看懂怎么用 | 有目录但说明少 | 文件堆在一起 |
| 工具复用 | 模板、提示词、评分都有 | 有工具但不完整 | 只有聊天记录 |
| 流程完整 | 有 SOP 和使用顺序 | 有流程但缺验收 | 不知道下一步 |
| 反馈机制 | 有评分或复盘标准 | 有反馈但不具体 | 没有改进机制 |
| 第 3 周衔接 | 有真实项目候选 | 项目还需收窄 | 和真实工作无关 |

## 3. 通过标准

- 至少 3 个可复用文件。
- 至少 1 个 SOP。
- 每个文件有使用场景和人工检查点。
- 能提出第 3 周真实项目候选。
