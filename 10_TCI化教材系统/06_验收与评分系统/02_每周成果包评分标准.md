# 每周成果包评分标准

本文件覆盖三周成果包验收标准：第 1 周《个人 AI 基础提效包》、第 2 周《岗位 AI 实战包》、第 3 周《个人 AI 落地成果包》。

---

# 第 1 周：《个人 AI 基础提效包》评分标准

## 1. 成果包组成

第 1 周成果包至少包含：

| 章节 | 交付物 |
| --- | --- |
| Day01 | AI 使用边界清单 |
| Day02 | 个人提示词模板 v1 |
| Day03 | 产品理解卡 |
| Day04 | 竞品评论分析表 |
| Day05 | Listing 初稿 v1 |
| Day06 | Listing 修改稿 v2 与审核清单 |
| Day07 | 个人 AI 基础提效包首页 |

## 2. 周级评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 基础边界 | 清楚区分可辅助和不可交给 | 有边界但不细 | 没有安全边界 |
| 提示词复用 | 六段式模板可迁移 | 模板可用但场景少 | 只是一次性提示词 |
| 证据链 | 产品和评论都有证据 | 部分有证据 | 大量凭空生成 |
| 修改能力 | 有 v1/v2 和审核清单 | 有修改但理由少 | 把初稿当终稿 |
| 成果包索引 | 文件用途和顺序清楚 | 有目录但说明少 | 文件散乱 |
| 第 2 周衔接 | 能进入岗位场景 | 方向还偏大 | 无法衔接 |

## 3. 建议分值

总分 100 分。

| 维度 | 分值 |
| --- | ---: |
| 基础边界 | 15 |
| 提示词复用 | 15 |
| 证据链 | 20 |
| 修改能力 | 20 |
| 成果包索引 | 15 |
| 第 2 周衔接 | 15 |

## 4. 通过标准

- 至少包含 5 个第 1 周交付物。
- 有一页成果包首页。
- 至少 1 条可复用提示词。
- Listing 有 v1/v2 对比。
- 写出第 2 周岗位场景。

## 5. 讲师点评句式

```text
这一周的成果不是聊天记录，而是可以继续使用的基础工具包。
```

```text
这里已经有产品理解卡了，下一步要补证据来源，让后续 Listing 更稳。
```

```text
Listing v2 的修改理由写清楚了，这会帮助你下次更快判断 AI 初稿。
```

# 第 2 周：《岗位 AI 实战包》评分标准

## 1. 成果包组成

第 2 周成果包至少包含：

| 章节 | 交付物 |
| --- | --- |
| Day08 | 岗位提效诊断表 |
| Day09 | 广告素材方向表 |
| Day10 | 广告数据复盘表 |
| Day11 | 客服 FAQ 与回复库 |
| Day12 | 运营周报模板 |
| Day13 | 岗位 SOP 模板 |
| Day14 | 岗位 AI 实战包首页 |

学员可以按自己的岗位选择重点，但成果包必须说明每个文件的用途、输入资料和人工检查点。

## 2. 周级评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 岗位聚焦 | 围绕一个清楚岗位或场景 | 岗位方向基本清楚 | 文件来自多个方向，缺少主线 |
| 文件完整 | 7 个交付物基本齐全 | 缺 1 到 2 个，但主线可用 | 缺少关键交付物 |
| 使用顺序 | 有清楚首页索引和推荐路径 | 有目录但顺序不清 | 文件堆放，没有使用说明 |
| 人工判断 | 每个关键文件都有检查点 | 部分文件有检查点 | 直接复制 AI 输出 |
| 复用价值 | 下周能继续使用 | 可参考但需整理 | 做完一次就丢掉 |
| 第 3 周衔接 | 能自然推出真实项目 | 有项目方向但还偏大 | 无法进入落地项目 |

## 3. 建议分值

总分 100 分。

| 维度 | 分值 |
| --- | ---: |
| 岗位聚焦 | 15 |
| 文件完整 | 20 |
| 使用顺序 | 15 |
| 人工判断 | 20 |
| 复用价值 | 15 |
| 第 3 周衔接 | 15 |

## 4. 通过标准

满足以下条件即可通过：

- 至少包含 5 个第 2 周交付物。
- 有一页岗位包首页。
- 至少 3 个文件有使用场景、输入资料和人工检查点。
- 至少有 1 个 SOP。
- 写出第 3 周候选项目。

## 5. 讲师点评句式

```text
这个岗位包的主线比较清楚，能看出你想优化的是广告岗位流程。
```

```text
这里文件不少，但使用顺序还不清楚。建议在首页加一段“先用什么，再用什么”。
```

```text
这个模板可以复用，但需要补输入资料和人工检查点，否则别人接手会不知道怎么判断。
```

```text
第 3 周项目方向已经有了，下一步要把范围收窄到 7 天内能完成的小项目。
```

# 第 3 周：《个人 AI 落地成果包》评分标准

## 1. 成果包组成

第 3 周成果包至少包含：

| 章节 | 交付物 |
| --- | --- |
| Day15 | 落地项目选择表 |
| Day16 | 项目拆解表 |
| Day17 | 项目第一版 v1 |
| Day18 | 前后版本对比表与项目 v2 |
| Day19 | 可复用模板 v1 |
| Day20 | 7 天 AI 使用计划 |
| Day21 | 个人 AI 落地成果包首页 |

## 2. 周级评分维度

| 维度 | 好 | 中性 | 需要继续改 |
| --- | --- | --- | --- |
| 项目真实 | 来自真实工作，有使用者 | 项目真实但场景偏泛 | 只是练工具 |
| 链路完整 | 选择、拆解、v1、反馈、v2、模板、计划完整 | 缺少部分材料 | 只有最终结果 |
| 人工判断 | 有清楚取舍和修改理由 | 有修改但理由少 | 直接复制 AI |
| 模板复用 | 变量、示例、检查点清楚 | 可用但说明少 | 只能用一次 |
| 计划持续 | 7 天计划小而真实 | 计划偏满 | 没有后续 |
| 成果表达 | 真实克制、有证据 | 证据略少 | 夸大效果 |

## 3. 建议分值

总分 100 分。

| 维度 | 分值 |
| --- | ---: |
| 项目真实 | 15 |
| 链路完整 | 25 |
| 人工判断 | 20 |
| 模板复用 | 15 |
| 计划持续 | 15 |
| 成果表达 | 10 |

## 4. 通过标准

- 至少包含 6 个第 3 周交付物。
- 有项目 v1 和 v2。
- 有前后版本对比和修改理由。
- 有可复用模板。
- 有 7 天计划。
- 成果说明不夸大，只写可验证变化。

## 5. 讲师点评句式

```text
这份成果包的项目链路很清楚，能看到你从选择项目到模板化的完整过程。
```

```text
这里建议补一组 v1 到 v2 的对比，这样能力证据会更具体。
```

```text
成果说明可以更克制一点，只写已经发生和能验证的变化。
```
